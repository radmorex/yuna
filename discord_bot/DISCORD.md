# Discord-бот Юны — настройка

Бот на `discord.py` сидит в ваших каналах, ловит сообщения «Юна, …» / «Yuna, …» или упоминание `@Юна`,
пересылает их в ядро (`ws://127.0.0.1:8787/bridge`) и отвечает реплаем. По желанию — заходит в голосовой
канал и озвучивает ответы.

## 1. Создать приложение и бота

1. Откройте <https://discord.com/developers/applications> → **New Application** → имя «Юна» → Create.
2. Слева **Bot**:
   - **Reset Token** → скопируйте токен (показывается один раз). Это `DISCORD_TOKEN`. Никому не показывайте,
     не коммитьте, не вставляйте в скриншоты стрима.
   - **Public Bot** — лучше выключить, чтобы бота не мог добавить кто угодно.
   - В разделе **Privileged Gateway Intents** включите **MESSAGE CONTENT INTENT** и нажмите Save.
     Без него бот видит пустой текст сообщений и не будет реагировать на «Юна,» (упоминания работать будут).
     (Server Members / Presence — не нужны.)

## 2. Пригласить бота на сервер

1. Слева **OAuth2 → URL Generator**.
2. **Scopes**: отметьте `bot`.
3. **Bot Permissions**:
   - Text: `View Channels` (Read Messages), `Send Messages`, `Read Message History`
   - Voice (если нужен голос): `Connect`, `Speak`
4. Скопируйте сгенерированную ссылку внизу, откройте в браузере, выберите свой сервер → Authorize.

## 3. Узнать ID каналов, ролей и пользователей

1. Discord → Настройки пользователя → **Расширенные** (Advanced) → включите **Режим разработчика**.
2. ПКМ по текстовому каналу → **Копировать ID канала** → в `DISCORD_CHANNEL_IDS`.
3. ПКМ по голосовому каналу → **Копировать ID** → в `DISCORD_VOICE_CHANNEL_ID`.
4. ПКМ по себе/модератору → **Копировать ID пользователя** → в `DISCORD_ADMIN_USER_IDS`.
5. Настройки сервера → Роли → ПКМ по роли → **Копировать ID роли** → в `DISCORD_ADMIN_ROLE_IDS`.

## 4. Заполнить `.env` (в корне проекта)

```dotenv
DISCORD_TOKEN=вставьте_токен_сюда
# Админы (через запятую): их команды Юна выполняет (смена наряда и т.п.)
DISCORD_ADMIN_USER_IDS=123456789012345678
DISCORD_ADMIN_ROLE_IDS=
# Пусто = слушать все каналы, куда у бота есть доступ. Рекомендуется указать.
DISCORD_CHANNEL_IDS=111111111111111111,222222222222222222
# Голос (по умолчанию выключен)
DISCORD_VOICE_ENABLED=0
DISCORD_VOICE_CHANNEL_ID=
# Ядро и общий секрет моста (тот же BRIDGE_TOKEN, что читает ядро)
CORE_URL=http://127.0.0.1:8787
BRIDGE_TOKEN=длинная_случайная_строка
```

Сгенерировать `BRIDGE_TOKEN`: `openssl rand -hex 32`.
Переменные окружения процесса важнее значений из `.env`.

## 5. Установка и запуск

```bash
cd ~/security-lab/mira-cohost
uv venv .venv-py --python 3.12                      # один раз
VIRTUAL_ENV=.venv-py uv pip install -r discord_bot/requirements.txt

# сначала запустите ядро (оно открывает /bridge), затем:
.venv-py/bin/python -m discord_bot.bot
```

Если `DISCORD_TOKEN` пуст — бот напишет об этом и спокойно выйдет (код 0), остальная система работает.
Если ядро ещё не запущено — бот переподключается к мосту с паузой 1→2→4…30 с.

Проверка: в разрешённом канале напишите `Юна, привет!` — бот ответит реплаем (без пингов).

## 6. Голос (опционально)

1. `ffmpeg` нужен в PATH (`brew install ffmpeg`; уже стоит в `/opt/homebrew/bin/ffmpeg`).
   Можно задать путь явно: `FFMPEG_PATH=/opt/homebrew/bin/ffmpeg`.
2. В `.env`: `DISCORD_VOICE_ENABLED=1` и `DISCORD_VOICE_CHANNEL_ID=<id>`.
3. В ядре должен быть включён TTS (иначе `audioUrl` пустой и озвучивать нечего).
4. Бот заходит в канал при старте (self-deaf), качает `audioUrl` только с хоста `CORE_URL`
   и проигрывает клипы по очереди, не перебивая.

Голос в Discord использует E2EE-протокол DAVE — поэтому требуется `discord.py>=2.7` (зависимость `davey`
ставится автоматически через `discord.py[voice]`).

## Поведение и защита

- Триггеры: сообщение начинается с «Юна» / «Yuna» + знак препинания (`Юна, …`, `юна! …`, `Yuna: …`) или
  содержит упоминание бота. «Миранда, привет» и «Юна привет» без запятой — не триггер.
- Лимит: не более 3 обращений от одного пользователя за 30 с (остальные молча игнорируются).
- Сообщения других ботов и личные сообщения игнорируются.
- Ответы отправляются с `allowed_mentions=none` — Юна не может пингнуть `@everyone`, роли или людей,
  даже если LLM это сгенерирует.
- Длинные ответы режутся на куски по 2000 символов.
- Токены в логах маскируются (`****abcd`).

## Частые проблемы

| Симптом | Причина |
|---|---|
| Бот онлайн, но молчит на «Юна,» | не включён MESSAGE CONTENT INTENT, или канал не в `DISCORD_CHANNEL_IDS` |
| `PrivilegedIntentsRequired` при старте | то же — включить intent в Developer Portal |
| `Bridge недоступен` в логе | ядро не запущено / другой `CORE_URL` / неверный `BRIDGE_TOKEN` |
| Нет звука | `DISCORD_VOICE_ENABLED=1`? у бота есть Connect/Speak? ffmpeg в PATH? TTS в ядре включён? |
